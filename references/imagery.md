# 根据 App 属性规划素材

本文只讨论 App 内实际使用的内容素材。开发前的 Image Gen 整屏高保真效果图见 layout-and-hifi.md：即使本产品不适合放任何照片或插画，也仍需生成整屏效果图并让用户确认。

## 判断先于生成

逐页记录核心任务、图片带来的具体帮助、占用空间和决定（无图/现有素材/需要生成）。内容浏览、旅行识别、教学解释可以受益；密集记录、计算、逐项检查可能更适合文字与系统图标。欢迎页可以有图，不代表操作页也必须有图。没有价值时明确选择无图，靠排版、色彩和交互完成品质。

避免从“工具 App”直接推导“全套不放图”。分别考虑场景识别、物品辨认、功能解释与完成反馈的价值；例如行程封面、装备缩略图、引导插画可以各有作用，密集操作页仍可保持无图。反过来，也不把某次旅行产品的封面方案强制套到记账或计算工具。

决定有图时，低保真必须画出图位、宽高比、主体大致构图和与文字的关系，而不只写一句“后续加图”或放无比例空框。注明来自用户、现有素材或计划生成；用户照片缺失时设计分类图标等替代状态。图位说明放在评审注释中，不能变成最终产品里的制作术语。

图文共同布局：标题、摘要、图片、列表与底部动作一起分配首屏空间。加入图片后重新检查文字分组和可见内容；不通过缩小所有文字抵消图片占用。占位构图只用于确认布局，不宣称是 Image Gen 已生成素材。

不要生成虚假的用户照片、医学证据或实际商品细节并当作真实数据。系统符号、简单图形和图表使用合适的代码或图标资源，不为它们强行调用位图生成。

## 布局阶段的资产清单

需要图片时，在项目 `design/assets-plan.json` 为每张素材记录：

```json
{
  "style": "本轮选定的媒介、调色、光线与材质",
  "assets": [{
    "id": "trip-cover",
    "screen": "trips",
    "purpose": "帮助识别旅行",
    "placement": "旅行条目封面",
    "aspectRatio": "3:2",
    "composition": "主体居右，左侧低细节留白",
    "cropSafety": "主体完整留在中央区域",
    "textOverlay": false,
    "source": "generate",
    "status": "planned",
    "path": null,
    "alt": "按最终画面填写"
  }]
}
```

这只是结构示例，内容必须按产品重写。无图项目只在 decisions.md 记录理由，无需空资产清单。探索占位应显示大致构图和比例，并在设计说明中区分占位与成品；不伪称图片已经生成。

## 整屏高保真确认后的内容素材生成

1. 按 [宿主适配](agent-compatibility.md) 使用已配置的图像生成工具，并读取其可用 Skill 或工具说明。优先使用宿主已有能力；不要求特定工具名，不索取 API key，不自行切换到新的付费服务。没有工具时说明缺口。
2. 先生成代表素材、查看画面，固定整体风格；以选定素材作参考生成其他必要素材。仅在风格需用户决定时提问，不逐张请求普通执行许可。
3. 每张提示词包含用途、显示比例、主体、构图、留白、媒介、色彩、光线、禁用文字/水印等实际约束。透明素材请求真正透明背景。
4. 保持共享角色、材质、色调和光线。修改使用编辑模式，明确保留项；遵循当前工具的引用机制，不编造工具参数。
5. 将工具实际输出复制进项目 assets 目录，更新 path/status/prompt/reference。不得只留下会失效的临时地址或写一个不存在的文件名。
6. 在原型实际位置查看裁切、主体、文字对比和小屏识别效果；必要时编辑图片或调整 object-position。不能以缩小整页掩盖问题。

交付说明标注 AI 生成素材；无需将制作说明撒进产品页面。图片缺失必须可识别，最终必需素材未生成时报告未完成。
