# 宿主能力适配

本 Skill 的设计流程共用一份 SKILL.md。按当前会话实际工具适配，不根据软件名称推断完整支持，也不要求另一个软件专有的工具名。`agents/openai.yaml` 只是 Codex 界面元数据，其他宿主无需执行或转换它。

## 开始与续接

首次使用或更换宿主时确认下表能力；用工具说明和必要的最小调用判断，不为探测能力提前生成付费图片。将影响阶段的能力缺口写入项目 `design/decisions.md`，能力变化后更新。沿用页面 ID、已确认图和用户选择；切换 Agent 不重开已确认阶段。

| 能力 | 实际要求 | 缺失时的处理 |
| --- | --- | --- |
| 文件读写 | 读取 Skill 相对资源，在项目内保存 HTML、图片与决定记录 | 仅提供对话内梳理，明确无法交付本地原型包 |
| 执行脚本 | 按需运行 Python 生成器或 Node 截图脚本 | 可直接写对比 HTML，或使用宿主浏览器；不自动安装运行时 |
| 参考图生图 | 输入当前页低保真及视觉参考，生成整屏图并保存可访问文件 | 完成已授权的前序阶段，保存提示词和待生成清单，停在生图阶段 |
| 浏览器操作与截图 | 打开实际原型，设置视口，操作并保存截图 | 保留可运行成果，标记布局/流程运行检查待验证；需要参考截图的生图步骤也暂停 |
| 看图 | 实际查看低保真、生成图与原型截图 | 保存成果但标记视觉检查待验证，不宣布效果图或视觉验收完成 |
| 隔离评审 | 可用的独立看图评审者 | 主代理复核并注明缺少独立评审，不伪造第二位评审 |

## 生图工具选择

1. 优先使用本会话已配置、支持参考图的图像生成能力，遵循其工具说明。有对应 imagegen 或其他生图 Skill 时先读说明；不编造 `image_gen`、MCP 或连接器名称。
2. Codex 中可使用当前可用的内置 Image Gen；Claude Code 等环境须有已配置的生图工具、MCP 或连接器；WorkBuddy 也须实际确认当前会话支持参考图与结果保存，不能只凭产品有“图片生成”入口就判定可用。
3. 不自动索取凭据、购买额度或切换到新的付费服务。新服务配置及额外费用按用户授权处理，不在项目文件或提示词中记录凭据。
4. 为每页保留页面 ID、提示词、输入参考路径、输出路径和工具来源。查看真实输出后再标为已生成；编辑时引用目标图并保存新版本。只有文本生图但不能输入参考图时，按本流程的生图能力缺口处理。
5. 工具失败时有限重试，保留成功页和未完成清单。等待能力恢复、用户提供外部完成的对应效果图，或用户明确调整流程；继续遵守原有确认点。

## 浏览器与路径

以本 SKILL.md 所在目录为资源根，不硬编码 `~/.codex`、`~/.claude`、开发者用户名或插件缓存路径。所有项目产物写入用户项目。Windows 路径有空格时使用宿主终端支持的引用方式；附带命令中的 `python3`/`node` 应替换为实际可用的解释器命令。

优先复用宿主浏览器能力；否则使用 [工具说明](tools.md) 中的 shoot.mjs。两条路径都须保存实际视口、操作、截图及待验证项。脚本执行成功不等于看图完成，浏览器检查不等于 iOS 原生验证。

## 安装后最小检查

要求 Agent 使用 iphone-ui，读取本文件和 `assets/style-explorer.html`，复述三个确认点及当前阶段可用能力。然后在独立项目目录用一个简单产品请求制作低保真，检查项目文件可打开、截图可查看、确认记录可续接；不在安装检查时自动进入正式生图。

兼容性报告分别记录“安装与资源读取”“基础流程”“完整流程”，附宿主版本、操作系统与证据。尚未运行的项写“待实测”，不以安装器支持名单替代运行验证。
