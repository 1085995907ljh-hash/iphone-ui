# iOS App 设计关键规则

适用：面向美国用户的 iPhone App。  
更新：2026-10-12。

本文采用简化中文。参考 ASD-STE100 的短句、主动表达和固定术语原则。ASD-STE100 是英文标准。本文不声明中文合规率。

## 1. 先记住这 6 条

1. 让用户看懂页面用途。
2. 让用户找到主要操作。
3. 让文字容易阅读。
4. 让按钮容易点击。
5. 让每次操作都有反馈。
6. 让价格和收费条件清楚。

这是学习用的归纳。通过上架审核，不代表设计优秀。

## 2. 安排页面

以下参考 [Apple：iOS 设计][ios]。

- 先写清页面的主要任务。
- 优先显示与任务有关的内容。
- 突出主要操作。
- 让次要操作容易找到。
- 保持相同功能的名称和外观一致。

例：食谱页先展示食材和步骤。收藏与分享放在辅助位置。

## 3. 选择跳转方式

以下是依据 Apple 指南整理的选择建议。

| 用户要做什么 | 优先考虑 |
|---|---|
| 切换主要区域 | 标签栏（Tab bar） |
| 查看当前对象的详情 | 进入下一层页面 |
| 临时完成一个小任务 | 面板（Sheet） |
| 进行复杂或长时间编辑 | 专门页面或全屏显示 |

依据：[标签栏][tabs]、[面板][sheets]。

- 用标签栏切换区域。
- 用按钮执行保存、删除等操作。
- 内容为空时，保留标签入口。
- 在空页面说明原因。
- 切换标签时，保留各区域的浏览状态。

## 4. 让用户能退出

以下参考 [Apple：面板][sheets]。

| 按钮 | 含义 |
|---|---|
| 返回（Back） | 回上一层或上一步 |
| 取消（Cancel） | 放弃未提交的修改并退出 |
| 完成（Done） | 完成任务或保存修改后退出 |
| 关闭（Close） | 关闭当前面板；保存方式需另行明确 |

- 不用“返回”代替关闭整个面板。
- 提供完成按钮时，也提供取消或上一步入口。
- 避免同时堆放返回、取消和完成按钮。
- 有未保存内容时，关闭前确认是否放弃。
- 避免连续叠加多个面板。

面板高度由内容决定。可调整高度的面板应显示顶部拖动条。

面板有两种行为：

- 模态：关闭面板后，才能操作原页面。
- 非模态：面板打开时，仍能操作原页面。

## 5. 让文字容易阅读

以下参考 [Apple：文字排版][type]。

- 优先使用系统字体和文字样式。
- 用字号和字重区分标题与正文。
- 相同用途的文字使用相同样式。
- 少用不同字体。
- 小字避免使用过细的字重。
- 支持动态字号（Dynamic Type）。
- 文字放大后，允许换行或调整布局。
- 不为保持固定高度而裁掉重要文字。
- 三行及以上的文字，避免使用紧密行距。

动态字号：用户调整系统文字大小后，App 中支持的文字随之调整。

初学时，可以先分三种用途：

| 用途 | 可选系统样式 |
|---|---|
| 页面标题 | Large Title 或 Title |
| 主要内容 | Body |
| 辅助说明 | Footnote |

这是起步方案。Apple 没有规定每个页面只能用三种样式。

## 6. 正确使用尺寸

以下参考 [Apple：无障碍][access]。

| 项目 | 参考值 |
|---|---|
| iOS 默认控件尺寸 | 44 × 44 pt |
| iOS 默认字号 | 17 pt |
| 普通小字号文字对比度 | 4.5∶1 |

- 用 44 × 44 pt 作为常规控件的起点。
- 为相邻控件留出间距。
- 小图标可以使用更大的点击区域。
- 17 pt 可作为正文起点。
- 按文字用途选择实际字号。

pt 是布局单位，不等于图片像素。

官方还列出 28 × 28 pt 的最小控件尺寸和 11 pt 的最小字号。不要把最小值当作默认目标。对比度要求也会随字号和字重变化。

[按钮指南][buttons]另行建议：按钮的点击区域通常至少为 44 × 44 pt。区分控件外观尺寸与点击区域。

## 7. 检查布局和无障碍

依据：[布局][layout]、[无障碍][access]。

- 避开会遮挡重要内容的系统区域。
- 键盘出现后，保持必要操作可访问。
- 文字放大后，检查重叠和截断。
- 检查浅色与深色外观下的文字对比度。
- 用文字或图形补充颜色表达。
- 为读屏功能提供清楚的控件名称。

### 适配不同使用方式

- 按实际可用空间调整布局。不要只按某个手机型号设计。
- 空间不足时，允许换行、增加行高或改成上下排列。
- 使用系统安全区域，避免系统栏和硬件区域遮挡重要内容。
- 背景可以延伸到屏幕边缘。重要文字和按钮仍需保持可访问。
- 关键手势提供按钮等替代入口。例如滑动关闭也提供关闭按钮。
- 用户开启减弱动态效果时，减少自动、重复和大幅移动的动画。
- 不只用声音或振动报告重要结果。同时提供可见反馈。

读屏功能 VoiceOver 会朗读界面信息。控件说明应表达用途，不描述装饰外观。

例：收藏图标应提供收藏用途和当前状态。不要只提供“红色爱心”这个名称。

### 最小检查流程

以下是实践建议，不是完整的无障碍认证清单。

1. 在较小的支持屏幕上完成主要任务。
2. 放大系统文字，再完成同一任务。
3. 打开键盘，检查输入框和必要操作。
4. 开启 VoiceOver，检查名称、顺序和操作。
5. 开启减弱动态效果与降低透明度，再检查界面。

排版建议：对齐同类内容。靠近相关内容。拉开不同分组。

间距和圆角应保持一致。Apple 没有为所有页面规定一套固定数值。

## 8. 使用新版界面

以下参考 [Apple：Liquid Glass][glass]。

Liquid Glass 是 Apple 的界面材质。它会随背景和交互状态变化。

- 优先使用系统组件。
- 将玻璃效果用于合适的导航和操作控件。
- 避免给所有内容卡片添加玻璃效果。
- 检查自定义背景是否遮盖系统效果。
- 检查降低透明度和减弱动态效果后的界面。

新版交互要点：

- 标签栏可以悬浮在内容上方。
- 可选择在滚动时收起标签栏。
- 半高面板与屏幕边缘留有距离。
- 面板充分展开时，外观会变得更不透明。

采用这些行为后，检查展开、收起和恢复操作。使用与目标系统版本匹配的[官方组件资源][resources]。

## 9. 补齐操作状态

依据：[加载][loading]、[进度提示][progress]、[警告弹窗][alerts]。下表是实践归纳。

| 状态 | 页面需要提供什么 |
|---|---|
| 没有内容 | 说明和下一步入口 |
| 正在处理 | 加载或进度提示 |
| 操作成功 | 清楚的结果 |
| 操作失败 | 原因和恢复办法 |
| 权限被拒绝 | 受影响的功能和替代办法 |

退出再回来时，检查用户是否丢失必要内容。

### 加载与进度

- 尽快显示可用内容。需要时，先显示占位内容。
- 等待期间，允许用户继续使用不受影响的功能。
- 能测量进度时，显示真实进度。
- 不能测量进度时，使用不显示百分比的加载提示。
- 处理停滞时，说明问题和可用操作。
- 可以安全中止时，提供取消入口。

### 错误与确认

- 说明具体问题。避免只写“错误”或错误代码。
- 提供有用的操作。例如重试或修改输入。
- 少用警告弹窗。普通信息尽量在相关页面内显示。
- 常见且可撤销的操作，避免反复要求确认。
- 不常见且不可撤销的破坏性操作，应先确认。
- 确认按钮写清动作。例如 Delete，不用含义模糊的 OK。

### 空页面与成功反馈

以下是教学示例。

- 首次使用：说明如何添加第一条内容。
- 搜索无结果：建议修改关键词或筛选条件。
- 加载失败：说明无法获取内容，提供重试。
- 收藏成功：更新收藏图标和状态，无需强制用户关闭成功弹窗。

实践规则：加载失败不等于没有内容。只有确认操作成功后，才显示成功状态。

## 10. 做好收费和上架流程

以下是相关[审核条款][review]的摘要。上架前需核对完整条款。

- 提交可正常使用的产品。对应 2.1。
- 让商店截图符合实际功能。对应 2.3。
- 在订阅前说明权益、价格和周期。对应 3.1.2。
- 有试用时，说明结束后的收费安排。
- 按规则请求权限和处理用户数据。对应 5.1.1。
- 支持创建账户时，提供 App 内发起删除账户的入口。

## 11. 面向美国用户

以下是实践建议。

- 使用真实英文文案排版。
- 用具体动作命名按钮。例如 Save photo。
- 使用清楚的日期格式。
- 支持合适的单位和用户偏好。
- 显示商店返回的本地化价格。
- 用目标用户验证设计。

## 12. 按钮、列表和表单

### 按钮：说明动作

依据：[Apple：按钮][buttons]。

- 用短文字说明动作。例如 Save Recipe。
- 图标含义不清楚时，使用文字。
- 用突出样式标记主要操作。每个视图通常保留一到两个突出按钮。
- 同组按钮优先用样式区分主次，不靠大小悬殊区分。
- 自定义按钮要有按下状态。
- 操作需要等待时，显示加载状态。
- 删除数据的按钮使用破坏性角色，不设为默认主要按钮。

### 列表：说明每行的用途

依据：[Apple：列表][lists]、[开关][toggles]。

- 每行使用简短、清楚的文字。
- 进入下一层时，使用右向箭头。
- 显示当前选择时，可以使用勾选标记。
- 开启或关闭设置时，使用开关。
- 开关样式用于列表行。列表外可使用有选中状态的按钮。
- 点击一行后，提供相应反馈。

### 表单：帮助用户输入

依据：[Apple：输入框][fields]。

- 为输入框提供用途说明。
- 需要持续显示用途时，保留独立标签。占位提示会在输入后消失。
- 邮箱使用邮箱键盘。数字使用合适的数字键盘。
- 密码使用安全输入框。
- 长段文字使用多行编辑区域。
- 按合理顺序移动输入焦点。
- 在合适时机检查输入。例如邮箱可在用户离开输入框时检查。

实践建议：输入有误时，说明修改方法。保留用户已经正确填写的内容。

## 13. 颜色与对比度

依据：[颜色][color]、[深色模式][dark]、[无障碍][access]。

记忆要点：按用途选色。保证文字清楚。用文字或图形补充颜色。检查不同外观。

- 按用途选择颜色。区分主要文字、辅助文字、背景和操作。
- 优先使用系统语义颜色。语义颜色按用途命名，并随显示设置调整。
- 保持颜色含义一致。不要让普通文字看起来像可点击按钮。
- 不单靠颜色表达状态。错误要有说明，选中项可加勾选。
- 检查文字与实际背景的对比度。普通小字号文字先按 4.5∶1 检查。
- 为自定义颜色提供浅色、深色和增强对比度版本。
- 尊重系统外观设置。深色模式需单独检查，不能只反转颜色。
- 在 Liquid Glass 上少用彩色。优先用背景色突出主要操作。
- 背景内容滚动后，再检查玻璃控件上的文字。

对比度表示前景与背景的明暗差异。数值越大，明暗区分越强。

计算示例：以下为不透明 sRGB 灰字与纯白背景的对比度。

| 文字颜色 | 背景颜色 | 对比度 | 是否达到 4.5∶1 |
|---|---|---|---|
| #999999 | #FFFFFF | 2.85∶1 | 否 |
| #666666 | #FFFFFF | 5.74∶1 | 是 |

这是计算示例，不是推荐固定色值。使用透明材质时，需检查合成后的实际背景。

## 14. 首次使用与权限

依据：[首次使用引导][onboarding]、[隐私][privacy]。

记住：先让用户做事。需要权限时，再说明用途。

### 首次使用

- 优先让用户通过操作学习。
- 只介绍当前任务需要的功能。
- 可选教程允许跳过。以后仍能从帮助或设置中找到。
- 用户跳过教程后，不要在每次启动时再次展示。
- 非必要设置推迟到需要时。先提供可用的默认值。
- 尽量让用户体验价值后，再请求评分或购买。

### 请求权限

- 只请求功能实际需要的权限。使用最小范围。
- 通常在用户使用相关功能时请求权限。
- 如果权限是 App 运行的必要条件，可以在首次引导中请求。
- 使用系统授权弹窗。用简短句子说明具体用途。
- 不要把“改善体验”当作完整的用途说明。
- 只在必要时增加授权前说明。不要模仿系统授权弹窗。

示例：用户点击“拍摄食谱照片”后，再请求相机权限。

英文用途示例：Use your camera to add photos to your recipes.

实践建议：用户拒绝后，保留不依赖该权限的功能。用户再次使用受限功能时，说明限制和恢复方法。不要反复催促授权。

## 15. 订阅付费页

本节适用于通过 Apple App 内购买提供的自动续订订阅。依据：[Apple 订阅指南][subscriptions]。

记住：买到什么、扣多少钱、多久扣一次，都要说清楚。

### Apple 明确要求

- 显示订阅名称、订阅周期和包含的功能或内容。
- 清楚显示完整的续订价格。使用本地化货币。
- 价格信息中，实际扣款金额最突出。
- 按年扣款时，突出全年总价。折算月价只能作为辅助信息。
- 有免费试用时，说明试用时长和结束后的价格。
- 为已有订阅的用户提供登录或恢复购买的方式。
- 在 App 和商店元数据中提供使用条款与隐私政策链接。

### 实践规则

- 明确说明自动续订。
- 按钮名称对应当前方案。有试用资格时，才显示开始免费试用。
- 切换方案后，同步更新价格、周期和试用说明。
- 提供容易找到的管理订阅入口，通向系统订阅管理界面。
- 恢复购买用于找回已有权益。不要把它写成退款。
- 免费功能仍可用时，付费页提供清楚的返回或关闭入口。

价格示例：年付方案突出“$59.99 / year”。辅助说明可写“约 $5 / month，按年扣款”。金额仅用于教学。

试用示例：7 天免费试用，之后每年 $59.99，自动续订，除非取消。仅对符合试用资格的用户展示。

## 16. 登录与账户

依据：[审核指南 5.1.1(v)、4.8][review]、[删除账户指南][account-deletion]。

记住：必要时登录。退出、删除和取消订阅要分清。

### Apple 明确要求

- 没有重要的账户相关功能时，允许不登录使用。
- 支持创建账户时，允许在 App 内发起删除账户。
- 删除入口要容易找到。仅停用账户不能代替删除。
- 删除包括账户和关联个人数据。说明依法保留的数据。
- 删除需要时间时，说明所需时间。完成后告知用户。
- 可以验证身份和确认删除意愿。不要设置多余障碍。
- 普通 App 不应要求用户联系客服才能删除。受严格监管的行业有例外。
- 用第三方登录建立或验证主要账户时，核对 4.8 的等效登录选项要求和例外。

4.8 要求的等效选项：只收集姓名和邮箱；允许隐藏邮箱；未经同意，不收集 App 交互数据用于广告。仅使用自有账户系统等情况有例外。

### 实践规则

- 登录前，说明登录的具体作用。例如跨设备同步食谱。
- 只收集当前任务需要的信息。
- 区分 Sign In（登录）和 Create Account（创建账户）。
- 使用密码时，提供显示密码和找回密码入口。允许粘贴密码。
- 登录成功后，回到用户刚才的任务。
- 在账户设置中分别提供退出登录、管理订阅和删除账户入口。
- 删除前说明数据影响和订阅处理方式。不要让用户误以为删除账户会自动停止续费。

| 操作 | 含义 |
|---|---|
| Sign Out | 退出当前登录，不等于删除账户 |
| Delete Account | 删除账户及应删除的数据 |
| Manage Subscription | 查看和管理订阅，包括取消续订 |

## 17. 界面图标

本节讲按钮和页面内的图标，不是桌面上的 App 图标。依据：[Apple 图标指南][icons]、[SF Symbols][symbols]。

记住：图标先表达意思，再考虑风格。

### Apple 设计建议

- 使用简单、熟悉且符合操作含义的图形。
- 同组图标保持相近的视觉大小、细节和线条粗细。
- 图标粗细通常与旁边的文字匹配。
- 按实际观感微调大小和位置。外框相同，不代表看起来一样大。
- 使用标准系统控件时，优先让系统处理选中外观。
- 自定义图标提供读屏可识别的名称。
- 自定义界面图标优先使用矢量资源。

### 实践规则

- 常见操作先从 SF Symbols 中选择。
- 不容易理解的操作配可见文字。例如“生成购物清单”。
- 同一操作在不同页面使用一致的图标和名称。
- 图案大小与点击范围分开处理。小图案也要容易点中。
- 读屏名称说明用途。例如“分享食谱”，不要写“向上箭头”。
- 新符号和动画先检查最低系统版本。旧系统需要可用的替代方案。
- 动画用于表达反馈或状态。不要让普通图标持续跳动。

| 常见操作 | Apple 标准符号示例 |
|---|---|
| 搜索 | magnifyingglass |
| 分享 | square.and.arrow.up |
| 删除 | trash |
| 关闭 | xmark |

这些符号仍需要页面上下文。关闭、删除和返回是不同操作，不要混用。

## 18. 间距、对齐和分组

依据：[Apple 布局指南][layout]。下方数值是练习示例，不是 Apple 统一规格。

记住：同组靠近，不同组分开，同级对齐。

### Apple 设计建议

- 按重要程度安排内容。考虑用户的阅读方向。
- 用对齐帮助用户扫读。用缩进表达上下级关系。
- 用留白、容器或分隔线表达分组。
- 内容过多时，逐步展示次要内容。
- 尊重系统提供的安全区域、边距和布局参考线。
- 文字变大时，允许换行、增高或改为上下排列。

### 实践规则

- 同组内部的间距，通常小于组与组之间的间距。
- 分组标题靠近它所说明的内容。
- 美国英语的连续正文通常左对齐。短标题或短提示可以居中。
- 同级标题使用共同的起始边。列表正文保持一致的起始边。
- 优先复用系统组件的布局。自定义区域复用一组间距值。
- 不要为了填满屏幕，把所有内容等距拉开。
- 留白已能说明分组时，不必给每行再加卡片、边框和阴影。

练习示例：食谱标题与简介间隔 8 pt；这一组与食材区间隔 24 pt。先理解两种距离的关系，再按实际文字和控件调整。

8 pt 网格和固定的 16 pt 页面边距，都不是适用于所有 iOS 页面的 Apple 强制规定。

## 19. 搜索与筛选

依据：[Apple 搜索指南][searching]。

记住：入口找得到，范围说得清，条件能撤销。

### Apple 设计建议

- 搜索是主要任务时，把入口放在主要位置。
- 尽量提供一个清楚的全局搜索入口。不同内容区也可以提供局部搜索。
- 通过标题、提示文字或范围控件，说明正在搜索什么。
- 需要时提供搜索建议，减少输入。
- 展示搜索历史前考虑隐私。展示时提供清除方式。

### 实践规则

- 搜索用于找关键词。筛选用于限制范围。排序用于改变顺序。
- 显示已启用的筛选条件。提供单项移除和重置入口。
- 重置筛选时，默认保留搜索词。全部清空要明确说明。
- 没有结果时，说明当前条件，并提供修改关键词或减少筛选的入口。
- 请求失败时，显示失败和重试。不要写成“没有结果”。
- 从详情返回时，保留关键词、筛选条件和原来的浏览位置。
- 搜索入口的位置服从导航结构。不要认定所有 iOS 搜索框都必须放在顶部。

例：搜索“鸡蛋”；筛选“15 分钟以内”；按“用时最短”排序。

无结果示例：“没有符合‘鸡蛋 + 15 分钟以内’的食谱。”提供“清除时间筛选”。仅在确认搜索成功且结果为空时展示。

## 20. 动效与操作反馈

依据：[Apple 动效指南][motion]、[触觉反馈指南][haptics]。加载与错误规则见第 9 节。

记住：按下有回应，等待有状态，完成有结果。

### Apple 设计建议

- 优先使用系统组件自带的动效。
- 自定义动效要有用途。不要用持续运动干扰阅读。
- 反馈动画要简短、准确。方向要符合手势和操作关系。
- 尽量允许用户打断动画。不要强迫用户等动画结束才能继续。
- 高频操作避免额外、重复的表演动画。
- 重要信息不能只靠动画表达。支持减弱动态效果，保留清楚的状态。
- 触觉反馈按系统规定的含义使用。成功与失败不要混用。
- 触觉反馈要短、适量且可以关闭。不支持或关闭后，功能仍可用。

### 实践规则

- 区分收到操作、正在处理和处理成功。
- 按钮按下的视觉变化，只说明收到操作，不代表已经成功。
- 需要等待时显示处理状态。会造成重复提交的操作，在处理期间防止重复触发。
- 真正完成后，再显示成功状态。反馈尽量出现在操作附近。
- 失败时说明问题和下一步。不要只让输入框抖动。
- 自定义触觉反馈与画面变化同步。不要给每次点击额外加震动。
- 不规定所有动画使用同一个时长。先复用系统行为，再按任务调整。

例：点击“生成购物清单” → 按钮回应 → 显示“正在生成” → 成功后展示清单。失败则保留原食谱并提供重试。

## 21. 界面文案

依据：[Apple 文案指南][writing]。

- 使用用户熟悉的词。删除不影响理解的词。
- 按钮优先写动作。例如 Save Recipe、Retry。
- 同一功能始终使用同一个名称。
- 按控件类型统一英文大小写。不要把所有英文都规定成一种格式。
- 错误提示靠近问题。说明如何修正，不责怪用户。
- 空页面说明下一步。重要的长期说明不要只放在空页面。
- 触屏操作使用 tap。不要照搬桌面的 click。

实践示例：把“操作失败”改为“无法保存食谱。请重试”。只有确认断网时，才说明网络原因。不要猜原因，也不要承诺未确认的数据状态。

## 22. 通知与提醒

依据：[Apple 通知指南][notifications]、[审核条款 4.5.4][review]。

### Apple 设计建议与审核要求

- 通知内容简短、有用。不要为同一件事反复通知。
- 避免在通知中展示敏感、私人或机密信息。
- 用户正在看相关页面时，优先更新页面，避免重复打扰。
- 不得把开启推送作为 App 可用的条件。
- 营销推送需要用户明确选择接收，并在 App 内提供退出方式。

### 实践规则

- 在用户设置提醒时解释用途，再请求通知权限。
- 点击通知后进入相关内容。需要登录时，登录后继续到目标位置。
- 目标内容已失效时，说明原因并提供可用去处。
- 让用户能修改或关闭自己设置的提醒。
- 日常提醒与营销消息分开设置。系统通知授权不等于同意营销。

例：用户设置晚餐提醒后，按约定时间发送“今晚的菜单已准备好”。点击后打开对应菜单。只有内容确实准备好时才这样写。

## 23. App 图标与商店截图

依据：[Apple App 图标指南][app-icons]、[审核条款 2.3][review]。

### App 图标：Apple 设计建议

- 用清楚的主体表达品牌。缩小后仍能识别。
- 只在必要时加入文字。避免细碎文字和过多细节。
- 当前 iOS 分层图标设计使用 1024 × 1024 px 方形布局。
- 使用 Icon Composer 预览图层和系统效果。让系统处理最终圆角遮罩。
- 检查默认、深色、透明和着色外观。各外观保留相同的核心特征。
- 不要把系统会动态生成的玻璃效果全部画死在素材里。

### 商店截图：审核要求

- 展示真实使用中的 App。不要只展示启动页、登录页或品牌海报。
- 可以添加说明文字和图像叠层，但不能虚构功能。
- 展示的内容需要额外购买时，要清楚说明。
- 使用虚构账户资料，不暴露真实个人数据。确保素材使用权。

实践建议：第一张说明主要用途，后续截图说明核心步骤和结果。每张突出一个重点。使用真实英文界面。上传尺寸按当时 App Store Connect 的设备要求检查。

## 24. 完整案例与验收

以下为教学归纳，不是 Apple 官方验收标准。以食谱 App 为例。

| 流程 | 设计需要说明什么 |
|---|---|
| 打开 App | 能做什么，主要入口在哪里 |
| 搜索食谱 | 搜索范围、筛选条件、无结果处理 |
| 查看食谱 | 食材与步骤分组，文字清楚，能返回 |
| 生成购物清单 | 按下回应、处理中、成功和失败 |
| 编辑清单 | 能修改，必要时确认删除，保留未完成内容 |
| 设置提醒 | 用户主动设置，权限用途清楚，拒绝后仍可使用其他功能 |
| 查看付费方案 | 权益、实际价格、周期、试用条件、恢复购买 |
| 管理账户 | 退出、删除和管理订阅分别说明 |

实际检查：完成一次主流程，再检查断网、拒绝权限、取消购买和返回重进。检查小屏、大字、深色、VoiceOver、减弱动态效果和最低支持系统版本。不要仅凭设计稿或构建成功判断体验合格。

### 10 条快速验收

- [ ] 看得懂：页面目的、文案和图标清楚。
- [ ] 找得到：主要操作、返回和退出容易找到。
- [ ] 点得准：控件容易点击，键盘不会挡住必要操作。
- [ ] 读得清：字号、对比度和分组合理。
- [ ] 有回应：按下、等待和结果都有反馈。
- [ ] 能恢复：空结果、失败、取消和重试都有处理。
- [ ] 不丢失：返回、重进和失败后保留必要内容。
- [ ] 能适配：小屏、大字、深色和辅助功能下仍可使用。
- [ ] 可控制：权限、通知、账户和订阅有清楚的管理入口。
- [ ] 不误导：收费、功能和商店展示与实际一致。

### 知识框架

结构：页面任务、导航和搜索。表达：文字、颜色、图标、间距和分组。操作：控件、输入、反馈和恢复。适配：屏幕、文字大小和辅助功能。信任：权限、通知、账户、收费和商店展示。

基础课程到此完成。后续按具体项目查阅规则和 Apple 原文，不把本文当作完整审核清单或审核通过保证。

## 25. 交付前详细检查

- [ ] 用户能看懂页面用途。
- [ ] 用户能找到操作和退出入口。
- [ ] 文字放大后仍可使用。
- [ ] 小屏和键盘出现时，必要操作仍可访问。
- [ ] 读屏能识别并操作主要控件。
- [ ] 关键手势有替代入口，界面响应减弱动态效果设置。
- [ ] 按钮容易点击。
- [ ] 按钮名称清楚，按下后有反馈。
- [ ] 列表行的箭头、勾选和开关用途正确。
- [ ] 输入框使用合适的键盘，错误有修改提示。
- [ ] 加载、成功、失败和空页面均已处理。
- [ ] 进度真实，失败后有恢复入口。
- [ ] 普通成功反馈不会用弹窗打断用户。
- [ ] 关闭面板不会无提示地丢失修改。
- [ ] 新版材质不影响阅读。
- [ ] 浅色、深色和增强对比度设置下，内容仍清楚。
- [ ] 错误与选中状态不只依赖颜色。
- [ ] 可选教程能跳过，之后仍能找到。
- [ ] 权限请求时机合理，用途具体，范围必要。
- [ ] 拒绝权限后，不相关功能仍可使用。
- [ ] 收费条件清楚。
- [ ] 实际扣款金额比折算价格更突出。
- [ ] 试用文案符合用户资格，说明后续收费。
- [ ] 恢复购买、管理订阅和条款入口可用。
- [ ] 登录有实际需要，登录后能继续原任务。
- [ ] 支持创建账户时，删除入口容易找到。
- [ ] 退出登录、删除账户和取消订阅的含义清楚。
- [ ] 图标含义清楚，同组风格一致。
- [ ] 难懂的图标配文字，图标按钮有读屏名称。
- [ ] 新符号和动画在支持的最低系统版本上可用或有替代方案。
- [ ] 同级内容对齐，分组标题靠近对应内容。
- [ ] 组内和组间的距离能表达关系。
- [ ] 文字放大后，间距和分组仍然清楚。
- [ ] 搜索范围清楚，已启用的筛选条件可见且能移除。
- [ ] 搜索无结果与请求失败有不同的提示和操作。
- [ ] 从结果详情返回后，搜索条件和浏览位置保留。
- [ ] 按下反馈、处理状态与最终结果有清楚的区别。
- [ ] 动画不阻挡后续操作，也不制造额外等待。
- [ ] 减弱动态效果、关闭触觉反馈后，操作结果仍清楚。
- [ ] 文案术语一致，错误提示具体且不猜原因。
- [ ] 通知可管理，点击后到达对应内容，营销消息有明确同意和退出方式。
- [ ] App 图标在不同尺寸和外观下仍可识别。
- [ ] 商店截图展示实际功能，说明额外购买，使用安全的示例资料。
