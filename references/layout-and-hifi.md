# 页面布局与 Image Gen 效果图

## 低保真说明的重点

每页采用这个简表，而非操作流程长文：

| 区域 | 内容与视觉安排 |
|---|---|
| 顶部 | 导航、标题、关键摘要；说明哪些不需要 |
| 中部 | 核心对象、排列方式、图文比例与信息密度 |
| 底部 | 主动作、辅助操作、项目内标签；固定或随内容滚动 |
| 视觉中心 | 第一眼对象、第二层信息、弱化的信息 |
| 首屏与延伸 | 首屏可见数量、滚动后的内容、长内容如何处理 |

比例按具体任务确定，不硬套上中下三等分。比较工具以视觉任务为中心，记账工具可能以金额和记录为中心；不要把所有 App 都做成大标题加卡片。交互约束单列简短备注，不能替代这张布局说明。

低保真用真实长度的文本、合理数量的数据及有构图意义的图片占位。先验证各主要页面，再记录用户确认的具体文件和版本。

## 低保真中的文字与空间

灰阶模型确认的不只是模块顺序，还包括内容的阅读节奏。配色和材质可以后定，文字层级、分组距离与图文比例不能推迟到高保真。

- 先区分页面标题、分组标题、核心内容、辅助说明与动作；通过字号、字重、位置和留白共同表达，不把所有内容都做成相近的中号文字。
- 首页标题可以突出；审阅、编辑、打包等操作页减少重复的大标题。导航标题与内容标题各有作用才同时保留。
- 核心对象名称、数量与状态先被看见。推荐理由、日期和备注为第二层；降低视觉权重不等于缩到难读或用过浅灰色。
- 名称和说明紧密成组，组内距离小于组间距离。不要给所有元素同样的 margin，也不要为分组给每一项套卡片。
- 起始尺度可试用：名称与说明 4–6pt、行内留白 12–16pt、组间 24–32pt，再根据内容和视口调整。这是设计启发，不是 Apple 强制值；HTML 的 CSS 像素仅用于原型模拟，不证明原生点尺寸合规。
- 行高须支持实际换行的英文、长物品名和多行理由。次要文案过长时优先删重复、收纳可展开内容，不用压缩字号或行高硬塞首屏。
- 图片、标题、摘要共同消耗首屏空间。加图后重新检查核心列表可见数量与主动作位置，不能在旧布局上简单插一张图就算完成。

在项目布局说明中记录采用的文字角色、间距关系和关键页首屏目标；目标按任务设定，不为所有页面强制同一字号、留白或行数。高保真可以细化这些尺度，但不得无说明地改变已确认的阅读顺序与密度。

## 低保真交付前检查

使用常规与窄屏手机的实际尺寸截图，直接看图，不只依赖 DOM、无报错或概览拼图：

1. 不靠彩色强调，能否指出第一眼对象、第二层信息和主动作？
2. 哪些文字属于同一组，是否能仅凭距离看出来？列表行与分组间是否有区别？
3. 大标题、说明和图片是否挤走了页面真正要处理的对象？首屏是否达到本页预设的信息目标？
4. 长名称、换行说明与数量是否对齐、可读？固定底栏是否允许末项完整滚动到可见区？
5. 图片位置是否实际画出比例与构图？无照片时的替代状态是否成立？

发现文字堆叠、平均间距或图片挤压内容时，在低保真中修正后再请用户确认。检查记录区分已看过的截图、未覆盖状态与原生未验证能力。

## 视觉方案选择

低保真确认后，先提供少量有实质差异、适合产品的视觉组合，通常 2–3 套即可；已有明确品牌规范时沿用，不制造无意义重选。每套同时展示背景/主色/强调色及其用途、标题与正文气质、图片媒介、按钮/列表/图标与边框阴影。用同一段真实内容的组件样本对比，不能只列色号或只改主色。

保留已确认的文字层级、图片图位、首屏密度与布局，不把视觉选择变成重新选页面结构。可以使用 HTML 设计板和局部组件，不把设计板称为已生成整屏高保真。图片尚未生成时明确标注拟采用的媒介，不能冒充已完成资产。

用户可以选择整套或指定混合搭配；记录具体版本和组合，必要时呈现合并后的样本。未选定前不生成正式整屏效果图、不进入开发；不把代理推荐当作用户批准。

## 效果图生成方式

1. 确认用户已选定配色与视觉方案，按已确认低保真主页面列出生成清单，默认一页一张；不把模块里的所有状态自动计为额外页面。读取 imagegen Skill，查看每页参考截图，确认内容加载完整、不是空白或错页后再引用。将各页自己的低保真截图作为结构依据、所选视觉方案作为风格约束。
2. 提示词注明：美国 iPhone iOS App、具体页面任务、美式英语界面、视口比例、上中下内容、首屏数量、主次关系、必须保留的布局、已有视觉参考。不引入桌面栏、营销海报或多余手机摄影外壳。
3. 使用内置 Image Gen 逐页生成整屏高保真图，在低保真基础上润色配色、字体、图标、控件与已规划图片。保留上中下布局、信息层级、间距关系、图片比例和首屏密度；无图片图位的页面保持无内容图片。风格参考只约束视觉表达，不能替换目标页内容。
4. 可以内部先生成一页校准风格，再连续完成其余主页面，不默认停下来请求代表页批准。按低保真总览相同顺序交付对应数量的图片，每页可单独放大查看，并保留低保真对照入口；不只交付拼贴小图。额外状态、其他设备尺寸或视觉方向仅在用户要求的范围内生成。
5. 查看每张图，检查布局偏移、遗漏内容、字号密度、对比度、图片比例与系统控件失真。图片中的细小文字不可靠时，另附准确文案，不把乱码原样实现。不能声称生成图已满足原生规范。
6. 用户修改时，引用目标图片、明确保留项与修改项，保存新版本。记录用户对具体版本的认可；单页确认不等于整套确认，全部主页面效果图确认后才进入开发。

建议目录：`design/low-fi/round-01/`、`design/high-fi/round-01/`，确认关系写入 `design/decisions.md`。每张效果图记录页面 ID、文件路径、引用的低保真/视觉图与待修改点。既有项目按既有结构保存，不为目录名重构历史。

## 两种图片用途不可混淆

- **整屏效果图**：开发前让用户确认“最终长什么样”，所有新完整设计都需要，即使产品页面没有照片或插画。
- **内容素材**：App 运行时实际显示的照片、插画等，由产品属性决定是否需要；详见 imagery.md。

效果图确认后，代码还原组件与文字；按需单独生成内容素材，不把整屏 PNG 铺成假 App。开发中提炼的精确色值应保持确认图观感，未展示状态按语义补齐，不再启动一轮独立配色审批。
